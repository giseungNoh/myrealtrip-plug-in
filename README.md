# 마이리얼트립 여행 큐레이터 (myrealtrip-curator)

기성 리뷰 플랫폼·인플루언서가 아니라, **지극히 개인적인 여행자의 "특별했던 경험"이 묻어나는 글**에서
숨은 명소·맛집을 발굴해 장바구니에 담고, 일정표나 구글 캘린더로 만들고, 그 위에 마이리얼트립 실제
상품을 추천해 연결하는 Codex 플러그인입니다.

## 전체 흐름

5개의 스킬이 파이프라인처럼 이어집니다. 사용자는 스킬 이름을 몰라도 자연어로 요청하면 되고,
**각 단계가 끝나면 플러그인이 먼저 다음 단계를 제안**합니다 — 사용자가 "다음엔 뭘 해야 하지?"를
매번 기억할 필요가 없도록 설계했습니다.

```
discover-local-spots        (여행지·장소유형·테마를 묻고, 개인 여행기에서 숨은 후보 발굴, 마이리얼트립 무관)
        │  "장바구니에 담을 번호를 골라주세요" → 사용자가 번호로 선택
        ▼
manage-travel-cart           (선택한 장소를 로컬 JSON 장바구니에 저장, 마이리얼트립 무관)
        │  "더 담으실 곳 있으세요? 다 담으셨으면 일정표 짜드릴까요?"
        ▼
build-itinerary               (Day별로 배치, 숙소·액티비티 포함 일정표를 Google Sheets로 생성)
        │                                  │
        │ "구글 캘린더에도 등록해드릴까요?"    │ 숙소·액티비티 슬롯
        ▼                                  ▼
sync-google-calendar     recommend-mrt-products  ← 여기서만 마이리얼트립 MCP 호출
   (구글 캘린더 커넥터 사용)      (mcp-servers.myrealtrip.com/mcp)
```

핵심 설계 원칙: **마이리얼트립 MCP는 마지막 상품 추천 한 지점에서만 사용합니다.**
장소 발굴, 장바구니, 일정 조립, 캘린더 등록은 플러그인이 새로 만드는 기능이며 마이리얼트립 앱에
지금 없는 기능이어도 동작합니다.

### 실사용 예시 (처음부터 끝까지)

1. **사용자**: "삿포로 온천 로컬 스팟 찾아줘"
   → `discover-local-spots`가 개인 블로그·현지 유튜버 글에서 후보 6~8개를 **현지어 리뷰 비율**과 함께 제시
2. **사용자**: "1번, 3번 담아줘"
   → `manage-travel-cart`가 장바구니(JSON)에 저장하고, 곧바로 *"다 담으셨으면 일정표 짜드릴까요?"*라고 되물음
3. **사용자**: "응, 3일 일정으로"
   → `build-itinerary`가 (숙소가 미정이면) `recommend-mrt-products`로 인근 숙소부터 추천 →
     장소들을 동네 단위로 묶어 Day별 동선을 짜고 여백 슬롯을 넣어 **Google Sheets**로 생성·공유,
     끝에 *"구글 캘린더에도 등록해드릴까요?"*라고 되물음
4. **사용자**: "응, 등록해줘"
   → `sync-google-calendar`가 실제 캘린더 이벤트로 등록

각 스킬은 이 순서를 몰라도 단독으로도 호출할 수 있습니다 (예: 이미 채워둔 장바구니로 바로
"일정 짜줘"만 요청하면 1~2단계를 건너뛰고 바로 시작합니다).

## 발굴 철학 — 무엇을 소스로 쓰고, 무엇을 배제하는가

이 플러그인의 차별점은 "어디서 찾느냐"에 있습니다. 관광객 쏠림을 재생산하는 소스는 의도적으로 피합니다.

**배제하는 소스**
- Tabelog·대중점평(Dianping) 등 **기성 집계 리뷰 플랫폼** — 상위 노출이 곧 붐빔·관광객화
- **인플루언서, 너무 유명한 블로거, 협찬성 글**

**채택하는 소스**
- 지극히 **개인적인 여행자의 "특별했던 경험"이 묻어나는 글** (개인 블로그·커뮤니티 글)에서
  언급된 명소·맛집. 목적은 **숨은 보석(hidden gem) 발굴**.
- 각 나라에서 **현지인이 실제로 많이 쓰는 검색 사이트·커뮤니티**를 경유해 수집.

**입력 흐름 (`discover-local-spots`가 먼저 묻는 것)**
1. 여행지가 어디인가 (예: 삿포로, 다낭)
2. 가고 싶은 장소 유형 (예: 온천, 스키장)
3. 이번 여행의 테마 (예: 관광, 먹방, 기타(guitar) 구매)

→ 답변에 맞춰 해당 국가에서 주로 쓰는 웹 검색 사이트·커뮤니티를 골라 개인 여행기를 탐색합니다.

**관광객 필터 (핵심 기능)**
- 후보 장소마다 **"현지어 리뷰 비율"** 등의 신호로 관광객 쏠림을 자동 감지합니다.
- 사용자에게 결과를 보여줄 때 **"현지어 리뷰 비율 약 N%"**를 함께 표기해, 얼마나 로컬한 곳인지
  한눈에 판단하게 합니다. (예: `⛩ ○○온천 — 현지어 리뷰 비율 약 82%`)

**커버 우선순위**
- 한국인이 많이 가는 해외 여행지 순으로 커버리지를 넓혀갑니다.
  (예: 일본 → 베트남 → 태국 → … 실제 순위는 최신 통계로 확정 예정)

## 질문 5문항

### 1. 무엇을, 누가, 어떤 상황에서 쓰나요?

해외여행을 준비하는 개인 여행자가, 여행지 맛집·장소를 검색할 때 "관광객만 가는 곳"이 아니라
현지인이 실제로 가는 곳, 그리고 남들이 잘 모르는 숨은 보석을 찾고 싶을 때 씁니다. 후보를 골라 담고,
일정표나 구글 캘린더로 정리하고, 필요한 입장권·투어가 있으면 마이리얼트립 상품으로 바로 연결받는
상황에서 사용합니다.

이 수요는 특정 취향이 아니라 대중 정서입니다(근거는 아래 통계):

- **90%**의 여행자가 "현지인처럼 살아보고 싶다"고 답하며, **62%**는 현지 문화를 경험하지 못하면
  "여행을 낭비했다"고 느낍니다. 밀레니얼의 **67%**는 "내 경험이 진짜가 아닐까 봐" 불안해합니다.
- 그러면서도 **91%**는 "커스텀 가능한, 잘 짜인 일정"을 원하고, **97%**는 일정의 20~30%를 자유
  시간으로 남기길 원합니다. 즉 완전 패키지도 완전 자유도 아닌, **"뼈대는 짜주되 현지 발견의
  여백을 남기는 반(半)자유형"**이 가장 큰 시장입니다.
- 한국 데이터도 같은 방향입니다. 해외여행 패키지 선택은 **13.9%**뿐이고, 여행사를 안 쓰는 이유
  2위가 "정해진 일정을 따라다니기 불편(48.9%)"입니다.

이 플러그인의 "발견 → 장바구니 → 일정/캘린더 → 상품 연결" 흐름이 바로 이 정서에 맞춰 설계되었습니다.

### 2. 왜 이 문제를 선택했나요?

계기는 개인 경험이었습니다 — 이탈리아 여행 중 여러 한국어 후기에 똑같이 반복 언급된 스테이크집을
찾아갔더니 한국인 관광객만 있었습니다. 이게 개인 취향의 문제가 아니라 구조적인 문제라는 것을
아래 공개 자료로 확인했습니다.

**① "SNS·블로그 맛집 = 관광객만 가는 곳"은 빅데이터로 확인된 현상입니다.**
SK텔레콤이 T맵 이용자 15억 건의 이동경로 데이터를 분석한 결과, 부산·여수·제주·전주·강릉 5개
도시의 SNS 인기 맛집 상위 10곳 중 관광객 비중이 최고 97%(여수·강릉 93~97%)에 달했습니다.
현지인이 실제로 가는 식당은 따로 있다는 뜻입니다.
— [한국일보(2018), SK텔레콤 T맵 빅데이터 분석](https://www.hankookilbo.com/News/Read/201808121529347972)

이런 불신은 최근 더 심화되고 있습니다. 해외 여행지 정보 탐색 채널 중 블로그 비중은 2020년 대비
20% 줄어든 반면 유튜브는 89% 늘었습니다 — "블로그 맛집을 안 믿는다"는 정서가 실제 행동 변화로
나타나고 있습니다.
— [한국경제(2026), MZ세대 여행 정보 채널 변화](https://www.hankyung.com/article/202602279687g)

**② 마이리얼트립 이용자도 정보 신뢰성·접근성 문제를 실제로 겪고 있습니다.**
2023년 보도 사례에서는 한 이용자가 마이리얼트립 예약 상세내역에서 나리타공항 터미널 정보를
찾지 못해 비행기를 놓쳤는데, 회사 측은 "E티켓상 정상 표기됐다"며 책임을 이용자에게 돌렸습니다.
경쟁 플랫폼(투어비스·인터파크투어)과 달리 카카오톡 등으로 한눈에 보이는 안내를 제공하지
않는다는 지적도 함께 나왔습니다.
— [스마트에프엔(2023), 마이리얼트립 여행정보 제공 문제 보도](https://m.smartfn.co.kr/article/view/sfn202307170065)

같은 맥락에서 직장인 커뮤니티(블라인드)에는 "가이드 난폭운전을 후기로 남겼더니 투어사 신고로
삭제됐다", "그래서 평점이 다 4.8~5.0으로 부풀려져 있다"는 이용자 증언도 있습니다. 익명 커뮤니티
게시물이라 사실관계가 검증된 자료는 아니지만, 다수의 공감 댓글이 달린 실제 이용자 목소리라는
점에서 참고했습니다.
— [블라인드, 마이리얼트립 후기 삭제 관련 게시글](https://www.teamblind.com/kr/post/%EB%A7%88%EC%9D%B4%EB%A6%AC%EC%96%BC%ED%8A%B8%EB%A6%BD-%ED%9B%84%EA%B8%B0-100-%EB%AF%BF%EC%A7%80%EB%A7%90%EC%9E%90-0d6ioy5z) (익명 게시물, 참고용)

**③ 여행 플랫폼 업계 전반에 구조적인 신뢰 문제가 있습니다.**
한국소비자원이 여기어때·야놀자·트립닷컴·아고다 이용자 1,600명을 조사한 결과(2024.12 발표),
14.0%가 이용 중 불만·피해를 경험했다고 답했습니다(고객센터 연락 안 됨 28.1%, 오버부킹으로 인한
예약취소 21.4%, 환급 지연·거부 20.5%). 이 조사에 마이리얼트립은 포함되지 않았지만, 같은 업계
구조(중개 수수료·후기 관리·고객센터) 위에서 벌어지는 문제라 참고 자료로 남깁니다.
— [베이비뉴스(2024), 한국소비자원 여행플랫폼 소비자 만족도 조사 보도](https://www.ibabynews.com/news/articleView.html?idxno=124777)

이 플러그인은 위 세 문제 중 **①(관광객 쏠림 정보의 신뢰성)**을 직접 겨냥합니다 — 기성 플랫폼·
인플루언서 소스를 배제하고 개인 여행기와 현지어 리뷰 비율로 필터링하는 것이 핵심 기능인 이유입니다.
②·③(정보 접근성, 후기·환불·고객센터 운영)은 이 플러그인의 범위 밖이지만, "발견 → 장바구니 →
일정/캘린더 → 상품 연결" 흐름 자체가 최소한 "이 추천이 어디서 어떻게 나왔는지"의 투명성은
높여준다고 판단했습니다.

마이리얼트립은 실제로 항공, 숙소, 투어·액티비티 등 여행 관련 상품을 탐색하고 예약할 수 있는 국내 최대
여행 플랫폼이며, 2025년 10월 기준 누적 가입자 1000만 명, MAU 500만 명 규모입니다. 또한 2023년부터
'마케팅 파트너' 프로그램을 운영해 승인된 파트너가 여행 상품 링크를 공유하면 예약 건수와 무관하게
발생 수익의 50%를 배분받는 구조를 이미 갖추고 있습니다. 이 플러그인은 그 구조 위에서, 지금은 없는
"발견 → 장바구니 → 일정/캘린더 → 상품 연결" 흐름을 새로 만들어 붙이는 것입니다.

### 3. 플러그인은 어떻게 작동하나요?

위 "전체 흐름" 다이어그램 참고. 스킬 5개로 나뉘며, 마이리얼트립 공식 MCP는
`recommend-mrt-products` 스킬에서만 호출합니다.

### 4. AI를 어떻게 활용했나요?

*(logs/ 폴더의 대화 기록이 곧 답변입니다. 요약: 문제 정의 → 마이리얼트립 API/MCP 공개 여부 검증 →
플러그인 vs 기존 기능의 경계 설계 → 실제 MCP 엔드포인트 확인 → 스킬 5개로 파이프라인 분해 → 각
SKILL.md 작성까지 전 과정을 AI와 대화하며 진행.)*

### 5. 어떻게 검증했나요?

*(실제로 Codex CLI에서 `.mcp.json`을 연결해 `recommend-mrt-products`를 실행한 로그를 남길 것.
나머지 4개 스킬은 마이리얼트립 없이도 로컬에서 동작 여부를 직접 실행해 확인할 것.)*

특히 `discover-local-spots`의 검색 품질은 **`search-verifier` 검증 에이전트**(`.claude/agents/`)로
확인합니다. 이 에이전트는 주어진 여행지·장소유형·테마로 실제 웹 검색을 수행해, 반환된 후보가
소스 원칙(개인 여행기 위주, 기성 플랫폼·인플루언서·협찬 글 배제)을 지키는지와 현지어 리뷰 비율
추정이 타당한지를 점수화해 리포트합니다. 새 국가 소스를 추가하기 전 검증 게이트로 사용합니다.
