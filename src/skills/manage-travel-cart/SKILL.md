# 목적

`discover-local-spots`에서 고른 장소, 또는 사용자가 직접 알려준 장소를 **여행(trip) 단위**로 저장한다.
외부 API나 인터넷 연결이 필요 없다 — 현재 작업 폴더 안의 파일에 저장하는 로컬 기능이다.

## 저장 위치와 형식

작업 폴더 기준 `./travel-cart/<trip-id>.json` 에 저장한다. `trip-id`는 사용자가 여행 이름을 안 정했으면
"목적지-대략날짜" 형태로 자동으로 만든다 (예: `rome-2026-08`).

파일 내용 예시 (JSON은 주석을 지원하지 않으므로, 아래는 각 필드가 무슨 뜻인지 옆에 풀어서 설명):

```json
{
  "trip_id": "rome-2026-08",
  "destination": "Rome, Italy",
  "items": [
    {
      "id": "1",
      "name": "Trattoria XYZ",
      "type": "restaurant",
      "source": "discover-local-spots (Roma Today 기사)",
      "note": "로컬 트라토리아, 한국어 블로그 언급 없음",
      "day": null
    }
  ]
}
```

각 필드 의미:
- `trip_id` : 이 여행을 구분하는 고유 이름. 파일명과 동일하게 맞춘다.
- `destination` : 목적지. 나중에 `recommend-mrt-products` 스킬이 이 값으로 마이리얼트립 상품을 검색할 때 쓴다.
- `items` : 장바구니에 담긴 장소 목록.
  - `day` : 아직 일정에 배정 안 됐으면 `null`. `build-itinerary` 스킬이 나중에 이 값을 채운다.

## 절차

1. **담기**: 사용자가 번호나 이름으로 장소를 지정하면, 해당 trip 파일이 없으면 새로 만들고, 있으면 `items` 배열에 추가한다. 같은 이름이 이미 있으면 중복 담지 않고 알려준다.
2. **보기**: `cat ./travel-cart/<trip-id>.json` 으로 읽어서 번호와 함께 사람이 읽기 쉬운 목록으로 보여준다.
3. **빼기**: 사용자가 지정한 항목을 `items` 배열에서 제거하고 파일을 다시 저장한다.
4. 파일을 고칠 때는 항상 전체를 다시 읽고, 그 위에 수정해서, 다시 전체를 쓴다. (부분 수정 명령어로 JSON을 깨뜨리지 않는다.)

## 다음 단계로 넘기기

장바구니가 어느 정도 찼고 사용자가 "일정 짜줘" 또는 "캘린더에 넣어줘"라고 하면 `build-itinerary` 스킬로 넘어간다.

## 하지 않는 것

- 여기서 마이리얼트립 상품을 검색하거나 추천하지 않는다.
- 여러 사용자가 공유하는 저장소가 아니다 — 지금은 한 사람의 로컬 파일이다. (나중에 창작자 공유 기능을 만들면 별도 스킬로 분리한다.)
