# 목적

`manage-travel-cart`가 저장해 둔 `./travel-cart/<trip-id>.json`을 읽어서,
아직 `day`가 비어 있는 장소들을 여행 일수에 맞춰 Day 1, Day 2 ... 로 배치하고
**숙소·액티비티 추천**을 포함한 완성형 일정표를 만든다.

# 이 플러그인의 성격 반영

이 플러그인은 "남들이 안 가는 곳"을 찾아주는 도구다. 장바구니에 담긴 장소는 대부분
**관광 명소가 아닌 로컬 식당·銭湯·동네 카페·현지인 거리** 등이다.

이 특성이 일정 설계에 영향을 준다:
- 유명 관광지 입장권 추천 필요성이 낮다 → `recommend-mrt-products` 호출 시 **숙소·액티비티 위주**로 검색한다
- 하루 일정을 꽉 채우지 않는다 — **여백(우연한 발견의 여지)**을 20~30% 남긴다
- 이동 동선은 "동네를 천천히 걷는다"는 감각으로 짠다. 하루에 여러 구를 왔다갔다 하지 않는다

# 절차

## 1. 사전 확인

- `./travel-cart/<trip-id>.json`을 읽는다. 파일이 없으면 장바구니에 먼저 담으라고 안내한다.
- 사용자에게 확인할 것 (이미 말했으면 다시 묻지 않는다):
  1. **여행 일수** (며칠)
  2. **숙소 위치를 이미 정했는지** — 정했으면 어느 동네인지
  3. **액티비티 관심 여부**

## 2. 숙소 추천 (일정 생성 전 선행)

**숙소 위치가 확정돼야 동선 설계가 가능하다.** 숙소를 아직 안 정했으면 일정을 짜기 전에 먼저 추천한다.

1. 장바구니 장소들의 주소·좌표를 분석해 **지리적 중심** 동네를 계산한다.
2. `recommend-mrt-products`를 호출해 해당 동네 인근 숙소를 검색한다.
3. 사용자가 숙소를 고르면 그 위치를 동선 설계 기준점으로 삼는다.
4. 숙소를 이미 정했으면 이 단계를 건너뛴다.

```
예시 안내 메시지:

"장바구니 장소들이 中央区·北区에 집중돼 있어요.
 숙소도 이 근처로 추천해드릴까요?
 → [마이리얼트립 숙소 추천 결과]
 어떤 숙소로 하시겠어요?"
```

숙소가 확정된 후 다음 단계로 넘어간다.

## 3. 동선 배치

1. 장소들을 **지역(동네·구) 단위**로 묶어 같은 날에 배치한다. 하루에 도시 전체를 왔다갔다 하지 않는다.
2. 장바구니에서 이미 `day`가 지정된 항목은 해당 날에 고정하고, `null`인 항목만 자동 배치한다.
3. 확정된 숙소 위치를 기준점으로 삼아 첫날·마지막날 동선을 인근부터 시작하도록 배치한다.
4. 각 Day 안에서 오전 → 점심 → 오후 → 저녁 시간 흐름으로 정렬한다.
5. **각 Day에 30분~1시간의 여백 슬롯**을 하나 넣는다 — "이 시간에 근처를 그냥 걷거나 우연히 발견한 곳에 들러도 좋아요"라는 문구로 표기.
6. 배치가 끝나면 `travel-cart` JSON의 각 항목 `day` 필드를 채워 다시 저장한다.

## 4. 액티비티 추천

사용자가 액티비티에 관심을 밝혔거나, 일정에 자연스럽게 어울리는 슬롯이 있으면 제안한다.
추천 기준:
- **현지인도 즐기는** 액티비티 — 관광객 전용 패키지 투어보다 로컬 체험 우선
  (예: 현지 요리 클래스, 새벽 수산시장 동행, 동네 자전거 대여, 현지 온천 입욕 예절 체험)
- 장바구니 장소의 테마와 연결되는 것 우선
  (예: 장바구니에 銭湯가 많으면 → "사우나 이용법·마나 체험" 액티비티 제안)
- `recommend-mrt-products`로 마이리얼트립 상품을 검색해 연결한다

## 5. 일정표 출력 — 스프레드시트 생성 및 공유

### 왜 이 방식인가

마크다운은 개발자 외엔 보기 불편하고 수정이 어렵다. 그래서 두 플러그인을 순서대로 쓴다:
1. **spreadsheets 플러그인**으로 서식·셀 포맷이 제대로 된 `.xlsx`를 로컬에 먼저 만든다
   (수식이 필요한 표는 아니지만, 퍼센트·날짜·하이퍼링크 같은 셀 서식을 제대로 입히는 데 쓴다).
2. **google-drive 플러그인**으로 그 파일을 Drive에 올려 브라우저에서 바로 편집 가능한
   공유 링크를 받는다 (Sheets 포맷으로 변환 업로드).

### 0. 연결 확인 및 설치 유도 (가장 먼저)

두 플러그인 다 확인한다 (`codex plugin list`).

- **spreadsheets** — `.xlsx` 실제 생성/서식을 담당. 없으면 설치 안내:
  ```
  codex plugin add spreadsheets@openai-primary-runtime
  ```
- **google-drive** — Drive 업로드·공유 링크 생성을 담당 (Drive·Docs·Sheets·Slides 커버). 없으면:
  ```
  codex plugin add google-drive@openai-curated
  ```
  설치 후 최초 사용 시 Google 계정 인증(OAuth) 창이 뜬다 — 사용자가 직접 로그인해야 한다.
- **Claude Code**: 연결된 스프레드시트 도구·Google Drive MCP 커넥터가 있는지 확인한다.
  없으면 사용자에게 연결을 안내하고 멈춘다.

플러그인/커넥터가 연결되면 실제로 어떤 도구를 제공하는지 먼저 확인한다 (버전마다 도구
이름·파라미터가 달라질 수 있으므로 하드코딩하지 않는다). google-drive만 없고
spreadsheets는 있으면, 일단 로컬 `.xlsx`까지만 만들고 업로드는 보류한 채 사용자에게
알린다 — 반대로 spreadsheets가 없으면 서식 있는 파일 자체를 만들 수 없으므로 먼저
설치를 유도한다.

### 생성 절차

1. (위 0단계에서 두 플러그인 연결 확인 완료)
2. spreadsheets 플러그인(`@oai/artifact-tool`)으로 아래 "Sheets 구성"대로 시트 2개짜리
   `.xlsx`를 만든다. `./travel-cart/<trip-id>-itinerary.xlsx`에 저장한다.
   - 현지어 리뷰 비율: 퍼센트 셀 서식(`0%`)
   - 날짜: 날짜 셀 서식
   - Google Maps·마이리얼트립 링크: 하이퍼링크로 삽입
   - 여백 슬롯 행: 🚶 이모지로 표기해 한눈에 구분
3. google-drive 도구로 이 `.xlsx`를 업로드하되 `mimeType: application/vnd.google-apps.spreadsheet`로
   지정해 Google Sheets 포맷으로 변환 업로드한다 (그래야 브라우저에서 바로 편집 가능해진다).
4. 파일명: `<trip-id> 여행일정` (예: `삿포로 2026-09 여행일정`)
5. 공유 설정: 링크 있는 사람 누구나 편집 가능으로 설정한다.
6. 사용자에게 로컬 `.xlsx` 경로와 Sheets 공유 링크를 함께 전달한다.

### 사용자에게 전달하는 메시지

```
✅ 일정표가 준비됐어요!

📊 Google Sheets로 열기 (편집 가능):
   https://docs.google.com/spreadsheets/d/xxxx

📎 로컬 Excel 파일: ./travel-cart/sapporo-2026-09-itinerary.xlsx
   (Drive 업로드 없이 바로 Excel로 열어도 됨)

PDF로 저장하려면: Sheets 상단 메뉴 → 파일 → 다운로드 → PDF

총 4일 일정, 장소 11개, 여백 슬롯 4개 포함됐어요.
숙소·액티비티 추천은 시트2에 있어요.
```

### 로컬 마크다운 (내부 저장용)

`./travel-cart/<trip-id>-itinerary.md`에 마크다운 버전도 함께 저장한다.
사용자에게 보여주는 용도가 아닌 **내부 참조용**이며, `sync-google-calendar`가
이 파일을 읽어 캘린더 이벤트를 만들 때 사용한다.

# 다음 단계로 넘기기

일정표가 완성되면 사용자에게 두 가지를 제안한다:

1. **"이 일정을 구글 캘린더에도 넣어드릴까요?"** → `sync-google-calendar` 스킬
2. **"My Maps에서 핀으로 보고 싶으시면 알려주세요"** → `manage-travel-cart`의 2단계 My Maps 생성

# 하지 않는 것

- 유명 관광지 입장권을 우선 추천하지 않는다 — 이 플러그인의 사용자는 그런 곳보다 로컬 스팟을 원한다
- 실제 이동 시간을 지도 API로 정밀 계산하지 않는다 — 상식적인 동선 배치로 충분하다
- 하루를 빡빡하게 채우지 않는다 — 여백이 없는 일정표는 이 플러그인의 철학에 맞지 않는다
- 마이리얼트립 상품 검색을 여기서 직접 하지 않는다 — `recommend-mrt-products` 스킬에 위임한다
